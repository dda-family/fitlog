## 2026-08-28 — 사전 개발 검토 (D1~D6)

### D1. 알림음/타이머 방식 — 포그라운드 + 화면 유지 기반
**결정**: 휴식 종료 알림음은 앱이 화면 켜진 포그라운드일 때 재생을 보장한다. 타이머가 도는 동안 무음 루프 `<video>`(muted, playsinline)로 화면을 깨워둔다(NoSleep 방식, 라이브러리 미사용). 상단에 큰 카운트다운을 고정 표시해 소리를 못 들어도 눈으로 확인 가능하게 한다.
**근거**: iOS WKWebView는 화면 잠금/백그라운드 시 JS·오디오를 중단한다. Wake Lock API는 iOS Safari 미지원. 따라서 "주머니에 넣어도 0초에 소리"는 보장 불가. 90/180초 짧은 구간이라 화면 유지 방식이 현실적.
**포기한 대안**: Web Push(서버 필요, 로컬 예약 알림 아님) → 범위 밖.
**영향 문서**: CLAUDE §5, PRODUCT §7, UX §7/§9, DATA §10/§11.

### D2. 루틴 = 템플릿 + 요일 매핑, 세션은 실제 날짜 기록
**결정**: 루틴을 요일에 하드코딩하지 않고 독립 "루틴 템플릿" 엔티티로 둔다. `요일 → 템플릿` 매핑은 설정에서 변경 가능(기본 화·목·토). **세션(기록)은 항상 실제 캘린더 날짜 + 파생 요일 + 실제 수행 템플릿을 저장**한다.
**근거**: 화요일 루틴을 수요일에 할 수 있어야 하고, 그때 기록은 그날(수) 기준으로 남아야 함. 요일 변경/분할 확장(4분할 등)도 데이터 구조를 깨지 않고 지원. 배포 전이라 마이그레이션 없이 v1에 반영.
**영향 문서**: DATA §4.1/§4.3/§4.4/§4.5, PRODUCT §3/§12, UX §4/§15/§16.

### D3. 어시스트 종목 판정 역방향
**결정**: `sideMode: assist` 종목(어시스트 딥스/풀업)은 판정 임계값은 동일하되, 증량 후보의 권장 방향을 반대로(보조중량 ↓ = 난이도 ↑) 표기한다. 판정 결과에 `progressionDirection`(`increase`/`decrease_assist`) 포함.
**근거**: 어시스트 종목은 보조중량을 올리면 오히려 쉬워지므로, 일반 증량 문구를 그대로 쓰면 오해를 준다.
**영향 문서**: PRODUCT §8.3, DATA §8.3/§8.4.

### D4. 미정 중량 — 지난값 자동채움 + 수동 승격
**결정**: 미정 종목(이두 컬·삼두 푸시다운, 스쿼트 시작값)은 시드에서 중량 `null`. 첫 기록값을 지난 사용값으로 자동 채움. 카드/가이드에 "이 값을 가이드 기본값으로 저장" 원터치 버튼 제공. 자동 승격은 하지 않는다(CLAUDE §2-9 원칙 준수).
**근거**: 사용자의 "첫 사용값을 디폴트로" 요구를 충족하면서 가이드 자동변경 금지 원칙과 충돌하지 않게 함.
**영향 문서**: PRODUCT §5/§6.1/§8.4, DATA §6, UX §5.1.

### D5. 워밍업 — 종목별 플래그
**결정**: 워밍업은 전역 기능이 아니라 종목별 `warmupEnabled` 플래그. 벤치·스쿼트만 시드 ON(벤치는 빈 봉 20kg×10~12, 30kg×5~8 안내 포함). 워밍업 세트는 `setType: warmup`로 저장하고 완료율·증량후보 판정에서 제외. 가이드 편집에서 아무 종목에나 켜고 끌 수 있음.
**근거**: 사용자가 벤치·스쿼트만 워밍업 예외를 원함. 전역 기능은 UI 복잡도만 키움.
**영향 문서**: PRODUCT §5/§8, DATA §4.2/§4.4/§7, UX §5.2.

### D6. 알림음 소스 — 자체 제작 차임
**결정**: iPhone 기본 시스템 알림음은 웹앱에서 접근 불가하므로, 자체 제작한 짧은 부드러운 차임(`assets/sounds/rest-end.mp3`)을 앱 asset으로 포함해 사용한다. SW 캐시로 오프라인 재생. 소리는 파일 교체로 언제든 변경 가능.
**근거**: iOS 시스템 사운드 라이브러리는 네이티브 앱/iOS 알림 전용. 애플 벨소리 직접 사용은 저작권 문제도 있음.
**영향 문서**: CLAUDE §5.3, PRODUCT §7.3, DATA §11.

## 2026-08-28 (2차) — D7~D9 확정

### D7. 타이머 = start-and-forget (제어 버튼 없음)
**결정**: 타이머에 일시정지·정지(끄기) 버튼을 두지 않는다. 시작하면 0초까지 자동으로 흐르고, 0초에 차임이 **단 한 번만** 울린다(반복/재알림 없음). 실행 중 타이머는 다음 `세트 완료`/`운동 완료`가 새 타이머를 시작하면 자연 대체된다.
**근거**: 사용자 실제 흐름이 "기록 → 시작 탭 → 폰 내려놓고 휴식 → 한 번 울리면 다시 운동"의 반복이라, 멈추거나 끌 대상이 없다. 버튼이 많을수록 운동을 방해한다.
**영향 문서**: UX §9, `timer.js`(addSeconds/정지 UI 제거).

### D8. 시드 데이터 확정
**결정**: `db.js`의 `SEED`를 PRODUCT_SPEC §5 표대로 채웠다. 미정 중량은 이두 컬·삼두 푸시다운 = `null`, 스쿼트 = `40`(시작값). 워밍업은 벤치·스쿼트만 `warmupEnabled: true`이며 `warmupSuggestions`로 표시(벤치: 빈 봉 20kg×10~12, 30kg×5~8 / 스쿼트: 빈 봉 20kg×10, 30kg×5 — 스쿼트 워밍업 수치는 기본 제안값, 편집 가능). 시드는 최초 1회만 깔리며(seedIfEmpty) 이후 가이드 화면에서 자유 편집·타인 수정 가능.
**영향 문서**: DATA §20, `db.js` SEED.

### D9. 기록 화면 MVP = 날짜별 조회만
**결정**: 기록 화면은 MVP에서 날짜별 조회만 제공한다. 주간 총 세트·부위별 집계·증량 후보 목록 등 통계는 이후로 미룬다.
**근거**: 초보 초기 단계에선 통계보다 기록 자체가 우선.
**영향 문서**: PRODUCT §11(통계는 "추가 가능"으로 유지, MVP 미포함).

## 2026-08-28 (3차) — 오늘 화면 개선 D10~D14 (Phase 1 실사용 피드백)

### D10. 날짜 직접 선택
오늘 화면 상단 날짜를 탭하면 날짜 선택기(네이티브 date)로 변경 가능. 기본값은 오늘. **템플릿 추천은 첫 디폴트로 고정**(날짜를 바꿔도 템플릿은 안 따라감 — "원래 그날 하려던 운동"의 의미 유지). 세션은 선택한 날짜·파생 요일로 기록.

### D11. 유산소 상시 카드 + 완료 순서
유산소를 종료 화면이 아니라 오늘 화면 맨 아래에 **상시 카드**로 노출(경사/속도/시간 입력 + `✓ 유산소 완료`). 유산소를 먼저 하는 날도 있으므로 완료 순서 자유. 흐름: 운동별 완료 → 유산소 완료 → 최종 "오늘 운동 종료". 종료 요약엔 유산소 완료 여부만 표시.

### D12. 즉석 운동 추가 (＋)
헤더 우측 `＋ 운동 추가`로 이번 세션에만 존재하는 운동 카드 추가. 이름 자유 입력(글자수 제한 없음, 예: "무릎모아 앉았다 일어나기"), kg·반복·세트(기본 3) 그 자리 입력. **가이드 정식 등록 아님**(Phase 3). 선택 운동으로 취급해 필수 완료율에 영향 없음. 삭제 가능.

### D13. 워밍업 중량·반복 입력 + 시각 구분
워밍업도 본세트처럼 중량·반복 스텝퍼로 실제 값 입력. 첫 추천값 자동 프리필. 본세트와 **확실히 구분되는 UI**(점선/앰버 톤/"W" 태그). 판정에서는 계속 제외(`setType: warmup`).

### D14. 목표 세트 초과 (＋ 세트 추가)
목표 세트를 다 채운 뒤 `＋ 세트 추가`로 4·5세트째 기록 가능. **추가 세트는 기록에 모두 저장**되지만, **증량후보/완료율 판정은 목표 세트(첫 N개)만** 기준으로 계산(추가 세트가 판정을 흔들지 않음). 화면엔 "(추가)"로 구분. 추가 세트 휴식은 90초 통일.

**영향 문서**: UX §4/§5/§9/§13, `app.js`, `styles.css`.

### Phase 2 (IndexedDB 저장) 구현 완료
- `db.js`: IndexedDB 래퍼 + 시드(seedIfEmpty) + recentSessions/lastResultFor/lastUsedWeight + clearAll.
- 정의(템플릿/운동/가이드)·설정을 DB에서 로드(최초 1회 SEED 시드). 세션은 `workoutSessions`에 저장.
- **지난번 기록** 자동 표시(운동별 최근 work 세트), **미정 중량**은 첫 기록값을 지난값으로 자동 채움.
- **기록 탭**: 날짜별 목록 + 상세(가이드/실제/평가/유산소). 통계는 여전히 이후(D9).

- IndexedDB 불가 브라우저는 SEED 폴백으로 열람만 되게 처리.

### D15. 워밍업 = 입력 즉시 자동 기록 (옵션 A)
워밍업 세트는 별도 저장 버튼 없이 입력하는 즉시 세션에 기록되며, 각 행에 `✓ 기록됨` 표시. 삭제(✕)만 제공.

### D16. 날짜 어포던스 = 화살표만
상단 날짜의 "변경" 글자를 빼고 `›` 화살표 + 점선 밑줄로 탭 유도만.

**영향 문서**: `db.js`, `app.js`, `styles.css`, UX §15/§18, DATA §4~§7.

세트 입력칸 기본 무게 우선순위: 이번 세션 직전 세트 → **지난번 실제 무게** → 가이드값. 가이드·지난번 두 줄은 카드에 계속 표시해 "계획 대비 실제" 감각 유지. 가이드 변경 자체는 Phase 3/AI 코치에서.

- **전체 데이터 초기화**: 2단계 확인 후 clearAll.

## Phase 4 완료 — AI 코치

`ai-bridge.js` 구현 + AI 탭 연결.
- **내보내기**: `프롬프트 생성` → 현재 요일배정·가이드(guideId 포함)·최근 4주 기록·증량 후보·제약(주3회·90분·유산소30분·데드리프트 제외·어시스트 역방향)을 텍스트로 조립 → 복사해서 ChatGPT/Claude에 붙여넣기.
- **가져오기**: AI가 준 `fitlog-guide-update` JSON 붙여넣기 → 검증(format/version/guideId 존재/숫자 유효성) → **변경안 diff를 항목별 체크박스로 표시** → 선택 적용.
- **적용**: update/remove/reorder 반영. 이전 가이드는 `guideHistory`에 `source:"ai-import"`로 저장. add는 안전상 이번 버전 제외(가이드 화면에서 직접 추가). 기존 세션 기록은 불변. 자동 적용 없음(항상 사용자 승인).

### 상태: MVP 전 Phase(1~4) 완료

## v23 (2026-09-23) — 탭바 뜸 / 운동 추가 검색창 가림 재수정

- **탭바 첫 실행 시 떠 있음**: 탭바 아래 빈 공간이 상단 safe-area(59pt)와 같다. iOS PWA가 첫 실행 때 뷰포트를 상태바만큼 짧게 잡고, 스크롤해야 복구되는 OS 버그라 CSS(env() 직접 사용)만으로는 해결 불가. → `index.html` 인라인 스크립트가 탭바 실제 바닥과 화면 바닥(standalone에선 `screen.height`)의 차이를 재서 `--vp-gap`으로 저장하고, `.tabbar`/`.modal-overlay`의 `bottom`을 그만큼 내린다. 정상이면 0이고, OS가 스스로 복구되면 재측정해서 0으로 돌아간다. 입력 중(키보드)에는 측정하지 않는다.
- **운동 추가 검색 시 검색창 가림**: iOS는 키보드가 떠도 레이아웃 뷰포트를 줄이지 않아 `inset:0` 오버레이의 시트가 키보드 뒤에 깔렸다. → 오버레이 top/height를 `visualViewport`(offsetTop/height)에 맞춘다. 키보드가 열리면 시트가 보이는 영역을 꽉 채워 헤더와 검색창은 위에 고정되고, 결과는 그 아래에서 스크롤된다.
- IndexedDB/데이터 변경 없음. 변경 파일: index.html, app.js, styles.css, service-worker.js.

## v24 (2026-09-23) — 탭바 문제 원인 재정의

- v23 실기 결과, 탭바는 제자리로 내려갔지만 **아래 59pt가 잘렸다**. 즉 첫 실행 때 앱 화면(WebView) 자체가 상태바 높이만큼 짧게 잡혀서 그 아래는 그릴 수 없다. `--vp-gap` 보정은 제거했다.
- 오늘 탭만 증상이 보이는 이유: 유산소처럼 내용이 짧으면 페이지가 스크롤되지 않는다. iOS는 스크롤이 한 번 일어나야 화면을 전체 높이로 다시 계산한다. 다른 탭은 내용이 길어 스크롤하는 순간 복구된다.
- 수정: `index.html` 인라인 스크립트가 standalone 세로 모드에서 `screen.height - innerHeight`가 20~100이면 짧게 잡힌 것으로 판단한다. 그러면 투명 여백을 잠깐 붙여 1px 스크롤했다 되돌린다(실행 시·복귀 시 최대 6회).
- 진단: 설정 → 앱 버전 옆에 `화면 첫값→현재값/화면높이 · 보정 횟수` 표시.
- 운동 추가 시트: 키보드가 열렸을 때 시트 높이에서 safe-area-top + 10px을 빼서 상단이 상태바·다이나믹 아일랜드에 가리지 않게 했다.
