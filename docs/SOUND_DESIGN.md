# Fitlog 사운드 설계 (v37)

> 운동 중 화면을 보지 않아도 "지금 무슨 일이 일어났는지"를 소리만으로 구분할 수 있게 한다.
> 이 문서가 소리의 기준이다. 소리를 추가·변경할 때 여기부터 고친다.

## 1. 점검 결과 (v36까지)

| # | 문제 | 원인 |
|---|---|---|
| P1 | 소리가 가끔 안 들림(알림 테스트 포함) | 재생 경로가 둘로 섞임: "얏호~"는 HTML `<audio>`, 준비 3·2·1·땡은 Web Audio(AudioContext). iOS에서 두 경로는 오디오 세션·무음 스위치 처리·백그라운드 복귀 후 상태(`suspended`/`interrupted`)가 서로 다르다. v35에서 Web Audio를 추가한 뒤부터 발생. |
| P2 | 첫 알림 테스트가 무음일 때가 있음 | 첫 터치의 `pointerdown` 언락(음소거 재생→정지)과 버튼의 언락이 동시에 실행 → 늦게 끝난 언락이 막 시작한 "얏호~"를 `pause()`. |
| P3 | 언락이 iOS 제스처 밖에서 실행될 수 있음 | 언락이 `await` 뒤에 다음 요소를 재생 → iOS는 사용자 제스처 호출 스택 안의 `play()`만 허용. |
| P4 | 소리 의미가 꼬임 | "얏호~" 하나가 버티기 끝 · 연속 세트 1바퀴 끝 · 휴식 끝을 모두 뜻함. 끝나기 전 예고음 없음. |

## 2. 원칙

1. **재생 경로는 하나.** 모든 효과음을 HTML `<audio>`로 재생한다(기존 "얏호~"가 실기기에서 안정적으로 들리던 경로). Web Audio는 쓰지 않는다. 짧은 신호음은 앱이 시작될 때 코드로 WAV를 만들어(외부 파일·CDN 없음) 각자 `<audio>`에 넣는다.
2. **언락은 한 곳, 한 번에, 동기적으로.** 첫 터치(및 이후 아직 언락 안 된 요소가 있을 때의 터치)에서 모든 효과음 요소를 같은 호출 스택 안에서 음소거 재생→정지. 실제 재생 중인 요소는 절대 건드리지 않는다. 언락 중에 재생 요청이 오면 언락이 끝난 뒤 재생.
3. **소리마다 뜻이 하나.** 같은 소리를 다른 의미로 재사용하지 않는다.
4. **겹치지 않게 시간 배치.** 끝 신호와 다음 준비 신호 사이에 최소 2초 간격.
5. **사용자가 누른 동작에는 소리를 내지 않는다.** (세트 완료 버튼 등 — 기존 횟수형 경험 유지)
6. `settings.soundEnabled === false`면 모든 효과음을 끈다(기본값 켜짐, 기존과 동일).
   - v44: 오늘 화면의 **🔊 알림음 켜짐 / 🔇 알림음 꺼짐** 토글(설정 › 알림에도 같은 토글)로 바로 바꾼다. 사용자가 고른 마지막 상태를 저장하고, 앱이 임의로 켜거나 끄지 않는다.
   - 꺼짐은 음량 0·음소거 재생이 아니라 **`audio.play()` 자체를 부르지 않는다** — 재생(`play`)과 언락(음소거 재생→정지) 모두 `FitlogSound.canPlaySound()` 하나를 지난다. 외부 음악(Apple Music·Spotify 등)보다 Fitlog 소리를 앞세우지 않기 위함.
   - 꺼져 있을 때 알림 테스트·소리 미리 듣기는 몰래 켜지 않고 "운동 알림음이 꺼져 있어요. 켜고 테스트할까요?"로 묻는다.
   - 타이머·준비 카운트다운·버티기·좌우 전환·연속 세트·휴식·자동 다음 단계는 그대로(소리만 없음). 화면 유지용 무음 video는 소리가 아니므로 그대로.

## 3. 소리 목록

| 키 | 이름 | 소리 | 언제 |
|---|---|---|---|
| `prep` | 준비 삑 | 중간 높이 짧은 "삑" | 준비 5초 중 마지막 3·2·1 |
| `go` | 시작 땡 | 높고 길게 울리는 "땡~" | 버티기 시작 순간 |
| `tick` | 마무리 똑 | 아주 짧고 가벼운 "똑" | 버티기·휴식이 **끝나기 5·4·3·2·1초 전** |
| `step` | 다음 띵 | 단음 "띵" | 한쪽(왼쪽) 또는 연속 세트 안의 한 운동이 끝나고 **다음 동작이 이어질 때** |
| `set` | 세트 완료 딩-동 | 내려가는 두 음 "딩-동" | 시간형 세트 또는 연속 세트 1바퀴가 **끝나서 휴식이 시작될 때** |
| `rest` | 휴식 끝 얏호~ | 기존 `rest-end.mp3` | **휴식 시간이 끝났을 때**(횟수형·시간형·연속 세트 공통, 기존과 같음) |

- "얏호~" = 휴식 끝(다시 운동할 시간)으로 의미를 하나로 고정한다. 횟수형 운동에서 원래 쓰던 뜻 그대로다.
- v35~v36에서 버티기 끝에 나던 "얏호~"는 `step`(다음으로) / `set`(세트 끝)으로 나뉜다.

## 4. 흐름별 타임라인

**단독 플랭크 45초 × 3세트, 휴식 90초**
```
[버티기 시작] → (준비 5초: 2초 조용 → 삑 삑 삑) → 땡~
→ 45초 버티기 … 40초 지점부터 똑 똑 똑 똑 똑 → 딩-동(세트 완료)
→ 휴식 90초 … 85초 지점부터 똑 똑 똑 똑 똑 → 얏호~(휴식 끝)
```

**사이드 플랭크 좌·우 각 30초**
```
준비(삑×3) → 땡~ → 왼쪽 30초 … 똑×5 → 띵(오른쪽으로)
→ 준비 5초(2초 조용 → 삑×3) → 땡~ → 오른쪽 30초 … 똑×5 → 딩-동 → 휴식 … 똑×5 → 얏호~
```

**연속 세트: 플랭크 45초 → 사이드 플랭크 좌·우 30초, 3세트, 휴식 90초**
```
준비 → 땡~ → 플랭크 … 똑×5 → 띵
→ 준비 → 땡~ → 왼쪽 … 똑×5 → 띵
→ 준비 → 땡~ → 오른쪽 … 똑×5 → 딩-동(1세트 완료)
→ 휴식 90초 … 똑×5 → 얏호~ → (다음 세트는 [연속 세트 시작]으로)
```

**연속 세트에 횟수형이 섞인 경우(푸시업 → 플랭크)**
```
푸시업 [✓ 완료 · 다음] (누른 동작이라 소리 없음) → 준비 → 땡~ → 플랭크 … 똑×5 → 딩-동 → 휴식 … 똑×5 → 얏호~
```

**횟수형(기존)**
```
[✓ 세트 완료] (소리 없음) → 휴식 90초 … 똑×5 (새로 추가) → 얏호~ (기존)
```

## 5. 세부 규칙

- **마무리 똑**은 시작 후 최소 2초가 지난 뒤부터만 낸다(아주 짧은 버티기·휴식에서 땡과 겹치지 않게). 예: 5초 버티기는 3·2·1만.
- 백그라운드에서 돌아왔을 때 이미 지난 신호는 몰아서 내지 않는다. 끝난 단계가 여러 개면 마지막 의미의 소리 하나만(세트가 끝났으면 `set`, 아니면 `step`).
- 연속 세트의 세트 후 휴식이 0초면 휴식 타이머를 시작하지 않는다(딩-동 직후 얏호~가 겹치지 않게).
- 시작음 `go`는 실제 시작 시각보다 1.5초 이상 늦었으면(백그라운드 복귀) 생략.

## 6. 설정 화면

- "알림 사운드 테스트"는 그대로 "얏호~"(휴식 끝)를 재생.
- 그 아래 **소리 미리 듣기**: 위 6가지를 하나씩 눌러 들어볼 수 있다(실기기 음량·구분 확인용).

## 7. 알려진 플랫폼 한계 (실기기 확인 필요)

- iOS는 앱이 백그라운드/잠금이면 JS와 소리를 멈춘다. 그 사이 끝난 신호는 복귀 후에만(그것도 한 번만) 난다.
- HTML `<audio>`의 음량은 iOS에서 코드로 조절할 수 없다 → 신호음 크기는 WAV 자체에 맞춰 두었다.
- 무음 스위치·AirPods·다른 앱 음악과의 관계는 기존 "얏호~"와 동일하게 동작해야 한다(경로가 같으므로). 실기기에서 확인.
